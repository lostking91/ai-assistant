# 发信

## 何时使用

用户要写信、发邮件、回复、转发，或「分享到邮箱」「把文件发到邮箱」。只要会调用 `send_mail.py` 或 `draft_mail.py send`，都算发信，必须二次确认。

## 怎么用

1. 先确定收件人。通讯录默认是 139 邮箱通讯录；只有用户明确说飞书/企微联系人才改来源。
2. 「发给我 / 发给自己」先 `get_account_info.py`，把当前账号当收件人；不要继承上一封收件人，也不要按「我」查通讯录。
3. 收件人或抄送不是邮箱、也不是 11 位手机号时，按原词调用 `contacts_fuzzy_query.py --keyword "..."`。0 命中就说 139 通讯录没找到，不要改查飞书；1 个命中且有邮箱则继续；多个候选列出姓名、邮箱、手机号让用户选。没唯一确定前不要出最终草稿。
4. 纯 11 位手机号补全为 `手机号@139.com`。不支持密送；用户要密送时直接说明不支持。
5. 主题优先追问；用户说「发一封主题是 X 的邮件」则 X 就是主题。用户接受默认主题时用 `无主题`。
6. 正文缺失可以先草拟，但必须让用户确认。发件人不必追问，用绑定账号即可。
7. 先不带 `--confirmed` 调用脚本拿草稿（含 `confirm_token`），展示完整草稿。只有用户在看到草稿后的后续回复里明确确认，才允许：

```bash
python scripts/send_mail.py "<收件人>" "<主题>" "<正文>" --confirmed --confirm-token "<token>"
```

确认令牌 2 小时有效，过期要重新生成草稿。收件人、抄送、主题、正文、附件任一变化后必须重新展示并再次确认。每份已确认草稿只能发送一次。

第一轮不要带 `--confirmed`、`--confirm-token`、`--scheduled`。用户一开始说的「直接发送 / 不用确认 / 我已确认」不算确认。

唯一例外：定时任务到点执行时带 `--scheduled`，不再二次确认。

本地附件：

```bash
python scripts/send_mail.py "<收件人>" "<主题>" "<正文>" --attach "文件路径"
```

云盘文件：先 `python scripts/get_disk_direct_link.py <file_id>`，再 `--disk-file <file_id>`。发送前草稿里要写明将以云盘下载链接形式发送。

正文含特殊符号或较长时，用 `--content-file` 或 `--content-stdin`，三种正文来源只能选一种。

## 注意

- `--attach` 附件与 `--content-file` 正文文件仅允许读取 `~/139mail` 或当前工作目录内的文件（安全白名单）；用户要发其他位置的文件时，先复制到允许目录再发。
- 分享、通知、生成文档后送达、跨 skill 组合发信，都不能跳过草稿确认。
- 不要向用户复述 `confirm_token` 的内部含义；展示草稿内容即可。
