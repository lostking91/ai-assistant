# 日程 / 待办

## 何时使用

用户说待办、日程、日历、备忘、计划安排时，默认走 139 邮箱日历，不要改查当前会话或其它助手的任务列表，除非用户明确指定。

## 查询怎么选

- 给出时间范围（今天、本周、某日到某日）：`python scripts/calendar_get_calendar_view.py --start-date YYYY-MM-DD --end-date YYYY-MM-DD`
- 给出标题或关键词：`python scripts/calendar_search_calendars.py --keyword "关键词"`
- 明确要日程消息、通知、邀请：`python scripts/calendar_get_message_list.py`
- 只说「查待办 / 查日程」、没有时间也没有关键词：先问「你想按时间范围查询，还是按标题关键词搜索？例如“查询今天的待办”或“搜索标题包含还款的待办”。」不要猜默认时间，也不要去查消息列表。

查看某条详情：

```bash
python scripts/calendar_get_detail.py <seq_no>
```

`seq_no` 来自列表对应序号，对用户用序号或标题。

## 怎么回复列表

必须跑脚本，不能只答「有/没有」。用序号、标题、时间组织列表，末尾加：`如需查看待办详情，请告诉我序号或标题。` 空结果原样采用脚本文案。

只有脚本给出可信总数时才能说「共 N 条」。按时间查询时，不要把接口的 `maxCount` 或当前页条数当成总数。

## 新增待办

事项（title）和时间必填，缺了先问，不要猜测。开始、结束至少给一端；只给一端时脚本会按另一端自动补 1 小时，确认信息里要展示补齐后的区间。

地点、提醒方式、提醒时间、备注不是必填。用户没说时直接展示默认值，不要再单独追问：

- 提醒方式：邮件（`--rec-my-email 1`，`--rec-my-sms 0`）
- 提醒时间：提前 5 分钟（`--remind-minutes 5`）
- 地点、备注：空

用户明确不设置提醒时必须传 `--rec-my-email 0`。从邮件提取的地点放进 `--site`。

确认时一次性展示这 6 项，不要拆成多步：

```text
请确认待办信息：
- 事项：项目评审
- 时间：2026-09-15 10:00:00 ~ 2026-09-15 11:00:00
- 地点：（无）
- 提醒方式：邮件
- 提醒时间：提前5分钟提醒
- 备注：（无）

确认后我再帮你添加。如需修改，直接说即可。
```

用户确认后再调用：

```bash
python scripts/calendar_add_new_unify_calendar.py \
  --title "项目评审" \
  --dt-start "2026-09-15 10:00:00" \
  --dt-end "2026-09-15 11:00:00" \
  --rec-my-email 1 \
  --remind-minutes 5
```

从邮件提取时加 `--subject "原邮件主题" --extmid "<mid>"`。时间格式必须是 `YYYY-MM-DD HH:MM:SS`。

## 新增成功怎么回复

先说固定首句，再按脚本字段原样列出，列表结束后立刻停止：

```text
已帮你创建以下日程，如需调整请直接告诉我:
- 事项：{title}
- 时间：{dtStart} ~ {dtEnd}
- 地点：{site 或（无）}
- 提醒方式：{reminderMethod}
- 提醒时间：{reminderText 或（无）}
- 备注：{content 或（无）}
```

`subject` 非空时再追加 `关联邮件：{subject}`，不要暴露 mid。不要改写成「周四上午」，不要补「日程已添加成功」「可在日历中查看」等尾句。
